# Learning Record 0003: 32-bit vs 64-bit

## Date
2026-06-25

## What I Learned
Two layers of type sizes exist in JCore:

1. **Classfile format** — architecture-independent, defined by JVM spec. References are stored as 2-byte indices in the constant pool, not raw addresses. Long is always 8 bytes, int is always 4.

2. **Runtime datatypes** — architecture-dependent, hardcoded in this codebase. `BCBasicDatatype.sizeInByte()` returns `4` for REFERENCE on line 123. The C kernel uses `u4_t` for pointers.

## Key Insight
The classfile format is designed to be portable — it stores type information at fixed sizes. The runtime must decide how big a reference actually is. JCore's runtime currently assumes 32-bit everywhere: `BCReference` stores `int value`, `ObjectDesc` uses 4-byte pointers, `ALL_ARRAYS_32BIT` forces 32-bit array indexing.

## What Would Change for 64-bit (ARM64)
- `BCBasicDatatype.REFERENCE` → return 8
- `BCReference.value` → `long`
- `addr_t` → `unsigned long long`
- 8-byte alignment for objects
- AArch64 assembly (currently x86-only)
- `System.java` → `os.arch="aarch64"`
